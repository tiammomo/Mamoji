# Mamoji 企业交付路线

## 交付目标

Mamoji 作为企业内部经营协同模块交付，默认聚焦以下闭环：

```text
费用或付款申请
  -> 预算校验
  -> 审批与财务复核
  -> 经营流水和账户记录
  -> 票据证据归档
  -> 异步通知、审计与经营报表
```

组织人力、税务、政策、家庭主体和备份 UI 根据客户范围单独启用。能力开关必须同时约束前端导航、路由、搜索结果和后端 API。

## 阶段 0：需求与交付基线

进入开发或客户环境部署前，确认：

- 企业主体、使用人数、角色、部门和数据范围；
- 费用、付款、预算和审批的现行制度；
- 身份来源、邀请流程以及是否需要对接 OIDC 或企业网关；
- 数据分类、敏感字段、附件类型和保留周期；
- 备份范围、RPO、RTO、审计保留和运维责任人；
- 客户环境的域名、证书、网络边界、对象存储和数据库策略。

输出物包括范围确认、权限矩阵、核心流程图、数据字典、部署拓扑和验收清单。未确认的数据权限和恢复责任不得留到上线后决定。

## 阶段 1：身份、公司与权限

目标：建立稳定的租户边界和最小权限访问。

- `access-management` 维护公司成员、角色和数据范围，不依赖可选员工档案；
- `company_memberships` 作为账号与公司的授权事实来源；
- 公司、部门、本人等范围进入 SQL 谓词；
- 禁用账号、邀请失效、跨公司访问和权限变更均可审计；
- 本地 Token 通过 `ActorIdentityProvider` 隔离，便于替换企业身份适配器。

上线门槛：跨公司和越权负向测试通过，关闭组织人力模块后仍可完成成员与权限维护。

## 阶段 2：费用、票据与审批

目标：形成可以追溯的申请和证据链。

- 明确草稿、提交、审批、驳回、撤回、入账和冲正状态；
- 非法状态转换返回统一 Problem Detail；
- 关键提交接受 `Idempotency-Key`，并由数据库唯一约束最终防重；
- 两名审批人并发处理同一申请时只能产生一个有效结果；
- 附件保存在 MinIO 私有 bucket，通过短时效签名地址访问；
- 审批轨迹保留操作者、公司、时间、原因和请求 ID。

上线门槛：正常、拒绝、撤回、重复请求、并发审批和附件失败路径均有集成测试。

## 阶段 3：预算、流水与账户

目标：让审批结果进入一致、可对账的经营事实。

- 定义预算可用、占用、确认和释放口径；
- 并发申请不能突破预算上限；
- 入账和冲正保留原始关联，不通过删除历史事实纠错；
- 每笔已入账申请可以追溯到审批、票据、流水和账户变动；
- 核心查询使用稳定分页、明确排序和与租户条件匹配的索引；
- 对账差异具有创建、处理、关闭和审计流程。

上线门槛：金额精度、余额一致性、预算竞争、重复入账和冲正测试通过。

## 阶段 4：异步事件与可观测性

目标：业务提交成功后，外部副作用可追踪、可重试、可恢复。

- 业务写入与 Outbox 事件在同一事务中完成；
- 消费器支持批量抢占、超时恢复、指数退避和 dead 状态；
- 通知和外部 Webhook 具备消费幂等；
- 每个请求生成或透传 `X-Request-Id`；
- Actuator、Prometheus、结构化日志和审计日志覆盖关键链路；
- 若接入 RocketMQ，仅替换发布适配器，业务服务不直接依赖 MQ SDK。

上线门槛：投递中断、超时、重复消费和恢复演练通过，积压与死信有告警和处置手册。

## 阶段 5：试点与正式上线

上线前按 [GO_LIVE_CHECKLIST.md](GO_LIVE_CHECKLIST.md) 和 [PRODUCTION_RUNBOOK.md](PRODUCTION_RUNBOOK.md) 执行：

1. 在预生产环境完成数据迁移演练和业务验收；
2. 确认生产配置 guard、强密码、邀请制、CORS 和私有对象存储；
3. 完成备份、恢复、回滚和故障通知演练；
4. 记录数据库版本、镜像版本、迁移校验和发布负责人；
5. 先在有限公司或部门试点，再按验收结果扩大范围；
6. 上线后持续观察错误率、P95 延迟、连接池、数据库锁等待、Outbox 积压和外部投递失败。

可用性、延迟、RPO、RTO 和数据保留期限由客户交付方案明确，不在公共仓库中假定统一数值。

## 变更原则

- 所有数据库变更通过 Flyway migration 管理；
- 兼容性重构保持现有 API，破坏性变更必须提供版本和迁移说明；
- 高风险变更先补回归测试，再按模块小步迁移；
- 不因技术偏好拆微服务，以吞吐、隔离、故障域或团队边界作为拆分依据；
- 不提交真实企业名称、证件、员工、薪酬、票据、税务或银行数据。
