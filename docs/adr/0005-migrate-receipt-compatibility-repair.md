# ADR 0005：以 Flyway 接管票据兼容回填

- 状态：Accepted
- 日期：2026-09-05

## 背景

拆分 demo 初始化器后，生产 Spring 上下文仍保留 `ReceiptVoucherDataInitializer`。它在每次应用启动时读取全部票据，调用领域策略补齐历史派生默认值，再以乐观锁逐条写回。即使数据已经完成修复，生产实例仍需要构造该 Bean 并执行全表查询；多实例同时启动时也会扩大无意义读写和版本竞争。

这些默认值是历史版本升级所需的一次性数据转换，不属于长期应用启动职责，应由数据库版本迁移保证只执行一次并记录结果。

## 决策

1. 新增 V27 Flyway migration，在 PostgreSQL 单事务内集合化计算并回填历史票据的税期、验票、抵扣、报销、审批、入账状态、会计凭证号、会计分录、入账时间和文件存储默认值。
2. 回填规则与 `ReceiptVoucherPolicy.hydrate` 的既有语义保持一致；只有派生字段实际变化的票据才更新 `updated_at` 并将 `version` 增加一次，已经完整的数据不产生版本变化。
3. 迁移在任何改写前预检 `amount`、`tax_amount` 与 `tax_rate`。存在无法解析的历史金额或税率时明确失败，整个 V27 事务回滚并保持 schema 版本为 V26，禁止以零值静默替代损坏数据。
4. 删除生产 `ReceiptVoucherDataInitializer` 和仓储中的 `repairLegacyDefaults` 全表修复入口。`DemoReceiptVoucherDataInitializer` 继续仅在 demo 模式注册，并只依赖企业样例初始化顺序。
5. 使用真实 PostgreSQL 测试覆盖成功回填、已完整数据不改版本、非法金额整批回滚，以及生产 Spring 上下文不存在票据初始化 Bean。

## 数据迁移

V27 不改变 HTTP 契约和表结构，但会按现有领域规则更新缺失或仍为旧占位值的派生字段。金额和税率字段本身不被改写；无效数值会阻止迁移。执行前必须保留数据库备份，并在升级副本核对票据状态、会计分录和凭证号。

## 影响

- 生产应用启动不再扫描或改写 `receipt_vouchers`，票据兼容数据只在升级到 V27 时处理一次。
- 迁移执行记录成为历史回填完成的权威证据，不再依赖每个应用进程重复判断。
- 应用运行期仍由 `ReceiptVoucherPolicy` 为新票据初始化派生字段，并在读取时兼容 hydrate；本决策不改变新建、审批或入账用例。

## 回滚

V27 是前向数据迁移，不通过删除 Flyway 历史记录回滚。发布失败时先停止新版本应用并从迁移前备份恢复；若迁移已经成功但应用镜像需要回退，旧版本的幂等启动修复可以读取已回填数据，不会把字段恢复为旧占位值。发现规则问题时应发布新的前向 migration 修正。
