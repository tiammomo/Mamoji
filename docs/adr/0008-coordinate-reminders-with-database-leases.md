# ADR 0008：以持久化租约协调定时提醒

- 状态：Accepted
- 日期：2026-09-05

## 背景

通知提醒每分钟扫描税务事项、员工合同/试用期和票据截止日。通知表的去重键能阻止同一天同一收件人的重复记录，却不能阻止每个后端实例都执行相同全表读取；仅使用进程内 `@Scheduled` 或事务 advisory lock 也无法阻止两个实例先后重复运行同一周期。

任务执行可能在扫描中途失败或随实例崩溃。协调机制既要限制一个周期只有一个拥有者，也必须允许超时接管，并阻止旧实例在接管后覆盖新实例的任务状态。

## 决策

1. Flyway V30 创建 `scheduled_job_leases`，保存任务名、当前 token、租约截止时间、下一运行时间、最近开始/完成/失败时间和错误摘要。
2. `ScheduledJobLeaseRepository` 使用单条 PostgreSQL UPSERT 和数据库 `CURRENT_TIMESTAMP` 认领到期任务，避免实例时钟偏差和先查后写竞态。
3. `DistributedJobCoordinator` 仅在认领成功后执行任务；完成和失败写入必须匹配当前 token。租约过期后新实例可生成新 token 接管，旧实例回写被 fencing 拒绝。
4. `notification-reminders` 完成或失败后按配置周期推进 `next_run_at`；任务部分执行后仍由通知业务去重键保证安全重试。
5. `scheduled_job_leases` 是运行协调状态，不导出到应用结构化备份；恢复业务快照时将其清空，由下一次调度重新认领。

## 影响

- 多实例触发同一个提醒周期时，只有一个实例扫描业务数据。
- 实例崩溃不会永久锁死任务；接管时间由 `MAMOJI_NOTIFICATION_REMINDER_LEASE_MS` 控制。
- 过短租约可能让仍在运行的慢扫描被接管，因此生产值必须高于完整扫描的 P99 耗时。
- 本决策不解除单实例生产保护；首次管理员和首个公司的启动编排仍需单独收口。

## 验证

真实 PostgreSQL 集成测试并发发起两个认领并断言只有一个成功，随后模拟租约过期和新 token 接管，验证旧 token 无法完成、当前 token 可以记录失败。结构迁移测试校验表字段和业务约束，结构化备份恢复测试校验租约表被清空。

## 回滚

V30 只新增独立运行态表。应用回退时旧版本不会读写该表；保留 Flyway 历史和表数据，后续通过前向 migration 调整。不要删除已发布 migration。
