# ADR 0019：为票据对象写入增加企业容量与事务补偿护栏

- 状态：Accepted
- 日期：2026-09-05

## 背景

票据上传先写 MinIO，再在同一数据库事务中创建凭证、附件摘要、审计和 Outbox 记录。数据库提交失败时，已经写入的对象不会随事务回滚，长期运行会产生无业务引用的孤立对象。另一方面，应用只限制单文件 10 MB，没有企业维度的累计容量上限；多副本同时上传时，仅靠进程内判断也会共同穿透水位。

生产备份已在维护窗口同时保护 PostgreSQL 与整个 MinIO volume，但备份不能代替在线写入治理。需要先阻止新的可预防孤立对象和容量失控，再独立建设历史对象盘点与保留策略。

## 决策

1. 生产配置增加 `MAMOJI_RECEIPT_STORAGE_MAX_BYTES_PER_COMPANY` 与 `MAMOJI_RECEIPT_STORAGE_WARNING_PERCENT`。硬上限必须为正整数，预警比例必须位于 1–99；生产环境脚本和启动 guard 双重校验。
2. 每次持久化上传在当前数据库事务中取得 `receipt-storage:<companyId>` PostgreSQL advisory transaction lock，再汇总该企业已提交、provider 为 `minio` 的对象大小。已有附件优先使用 V32 已固化为不可变证据的 `receipt_file_hashes.file_size`，历史上没有摘要记录的对象才回退到凭证大小，避免普通凭证字段修改绕过配额。批量上传与多副本上传因此使用同一串行容量边界。
3. 超过硬上限时返回 HTTP 507，不调用对象存储；达到预警水位时允许上传并记录不含高基数标签的 Prometheus 计数器及带企业 ID、对象数、用量和上限的日志。
4. MinIO 写入只允许发生在已激活事务同步的数据库事务内。写入成功后返回一条待确认引用的 write lease，并注册 `afterCompletion` 回调；只有事务提交且该文件已经完成凭证、摘要、审计和 Outbox 写入时才保留对象。事务回滚或批量上传中单文件失败但外层事务提交时均调用 MinIO 删除；成功和失败分别计数，删除失败不掩盖原始事务结果但必须输出错误日志。
5. 本批不自动删除历史孤立对象，也不按对象年龄自动淘汰财务证据。历史盘点、保留期限与人工确认后的清理必须作为独立变更交付。

## 影响

- 单企业票据对象用量不会因多实例并发而越过配置上限；已有用量高于新上限时，后续持久化上传会被拒绝，直到调整容量或完成受控归档。
- 常规数据库异常、提交失败和事务回滚不再遗留新对象。进程在上传与登记回调之间崩溃仍可能留下孤立对象，因此后续仍需要只读盘点作业。
- 配额以已提交票据元数据为准，不统计历史孤立对象，也不替代 MinIO volume 的磁盘监控和基础设施容量预留。
- 对象删除只用于当前请求回滚补偿；票据证据没有新增用户删除入口，保留和审计语义保持不变。

## 验证与回退

- 领域测试覆盖精确上限、预警边界、非法配置和 `long` 边界；JDBC 测试固定公司事务锁和只统计 MinIO 对象的聚合查询。
- 应用测试覆盖关闭对象存储时兼容元数据模式、无事务拒绝、配额拒绝、提交保留、回滚删除及删除失败计数。
- 全量后端、前端、脚本、Compose、备份维护和多副本烟测门禁保持通过。
- 本批不修改数据库 schema。回退代码与两个环境变量即可；回退前先确认没有企业依赖新配额作为合同控制，且保留应用日志用于排查已发生的未引用对象补偿失败。
