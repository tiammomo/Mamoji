# ADR 0014：类型化票据上传契约与批量结果

- 状态：Accepted
- 日期：2026-09-05

## 背景

票据 JSON 创建和更新完成类型化后，单文件与批量上传仍把所有 multipart 元数据收进 `Map<String, String>`。非法金额、日期和状态可能被静默替换为默认值；应用服务同时用嵌套 Map 组织成功与失败响应，使字段变更缺少编译期保护。两个上传端点使用相同业务元数据，但没有共享的显式契约。

## 决策

1. `POST /api/v1/receipts/upload` 和 `/batch-upload` 共同使用 `ReceiptUploadRequest`，通过 Spring multipart model binding 和 Bean Validation 校验公司/流水 ID、金额精度与范围、ISO 日期、状态白名单和文本长度。
2. 上传 DTO 映射到 `ReceiptUploadCommand`；应用服务不依赖 Web 层类型，也不再解析参数 Map。
3. 上传契约只接受票据基础、税务与报销元数据，不开放审批和会计写字段；这些状态继续由专属流程维护。
4. 单文件应用用例直接返回 `ReceiptVoucher`，批量用例返回不可变 `ReceiptBatchUploadResult` 与逐文件 `ReceiptUploadFailure`；API 层再映射为 typed response，并保持原 JSON 字段名。
5. 批量处理继续允许部分成功：通过入口校验的共享元数据应用到每个文件，单个文件的格式、存储或重复冲突仍进入 `failures`，不会使其他文件回滚。

## 影响

- 非法上传元数据在访问对象存储和数据库前以字段级 HTTP 400 拒绝，不再静默采用默认值。
- 单文件和批量上传共享同一输入约束，前端现有合法 FormData 与成功/失败响应结构保持兼容。
- 应用层上传入口和结果不再出现参数或响应 Map，后续增加字段会同时受到编译器、验证和边界测试约束。
- 文件内容校验、公司内 SHA-256 并发去重、对象存储错误映射及每批最多八个文件的规则保持不变。

## 验证与回退

- 真实 HTTP multipart 集成测试覆盖单文件非法元数据、批量非法元数据和合法上传字段持久化。
- 既有并发测试继续验证相同文件只有一个请求成功，另一个稳定返回冲突。
- 模块边界测试禁止上传/批量上传应用入口退回 Map，并固定 DTO→命令及 typed result 类型。
- 本次不修改数据库结构；回退代码提交即可，无需迁移数据或调整客户端。
